# 01 — Foundation: config, database, Prisma, health

**Goal:** a booting NestJS app with validated env, a Postgres schema matching the DDD, a Prisma service and a `/health` endpoint.
**ADRs:** 002, 015, 016. **Docs:** `iris-ddd.md` §3, §5.

## 1. Dependencies

Install: `@prisma/client @prisma/adapter-pg pg zod luxon @nestjs/schedule` and dev `prisma @types/pg @types/luxon`.
Check `npx prisma --version`. On Prisma ≥ 7, use `prisma.config.ts` + the `prisma-client` generator (as in DDD §3). On 6.x, use the `prisma-client-js` generator + `url = env("DATABASE_URL")` in the datasource, and record the choice in `spec/QUESTIONS.md`.

## 2. Remove scaffold

- Delete `src/app.controller.ts`, `src/app.service.ts`, `src/app.controller.spec.ts`. Replace `test/app.e2e-spec.ts` with `test/health.e2e-spec.ts`.
- `ObserveModule` (`@nestjs/observe`): register it **only** when `OBSERVE_APP_KEY` and `OBSERVE_APP_SECRET` are set. Otherwise omit it and pass no `instrument` option to `NestFactory.create`.

## 3. Environment (`src/config/env.schema.ts`)

zod schema. Parse `process.env` once at boot; on failure, print the issues **without values** and `process.exit(1)`. Export `type Env` and inject it via `ConfigModule` (custom provider token `ENV`, global module; do not use `@nestjs/config`).

| Var | Type / default | Rule |
| --- | --- | --- |
| `NODE_ENV` | `development\|test\|production`, default `development` | |
| `PORT` | int, default `3000` | |
| `DATABASE_URL` | url | required |
| `IRIS_TIMEZONE` | string | required; valid IANA zone (`luxon` `IANAZone.isValidZone`) |
| `IRIS_TOKEN_AGENT` | string ≥ 32 | required |
| `IRIS_TOKEN_GOOGLE_SCRIPT` | string ≥ 32 | required |
| `IRIS_TOKEN_ADMIN` | string ≥ 32 | required |
| `HABITICA_WEBHOOK_SECRET` | string ≥ 32, `[A-Za-z0-9_-]` | required |
| `IRIS_PUSH_TARGETS` | CSV of `GOOGLE_TASKS,GOOGLE_CALENDAR,HABITICA`, default empty | parsed to `PushPlatform[]`, dedup |
| `SYNC_WORKER_ENABLED` | bool, default `true` | `"true"/"false"` only |
| `SYNC_WORKER_INTERVAL_MS` | int ≥ 250, default `2000` | |
| `SYNC_WORKER_BATCH` | int 1–100, default `10` | |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN` | string | required iff any `GOOGLE_*` push target is set |
| `GOOGLE_TASKLIST_ID` | string | required iff `GOOGLE_TASKS` is set |
| `GOOGLE_CALENDAR_ID` | string | required iff `GOOGLE_CALENDAR` is set |
| `GOOGLE_CALENDAR_EVENT_MINUTES` | int 5–1440, default `30` | |
| `HABITICA_USER_ID`, `HABITICA_API_KEY` | string | required iff `HABITICA` is set |
| `OBSERVE_APP_KEY`, `OBSERVE_APP_SECRET` | string, optional | |

Conditional requirements are implemented with `superRefine`. Write `.env.example` with every variable, placeholder values and a one-line comment each.

## 4. Docker Compose (dev)

`docker-compose.yml`:
- `postgres`: `postgres:17-alpine`, port `5432:5432`, volume `iris_pg`, env `POSTGRES_USER=iris POSTGRES_PASSWORD=iris POSTGRES_DB=iris`, healthcheck `pg_isready`.
- An init script `docker/postgres/init.sql` creates the database `iris_test`.
- (The `iris-hub` service is added in spec 10.)

npm scripts to add:
```json
"db:up": "docker compose up -d postgres",
"db:migrate": "prisma migrate dev",
"db:deploy": "prisma migrate deploy",
"db:generate": "prisma generate",
"pretest:e2e": "dotenv -e .env.test -- prisma migrate deploy"
```
Use `.env.test` (committed, test-only secrets, `DATABASE_URL=postgresql://iris:iris@localhost:5432/iris_test`, `SYNC_WORKER_ENABLED=false`, `IRIS_TIMEZONE=America/Sao_Paulo`). Add `dotenv-cli` as a dev dependency. `vitest.config.e2e.ts` loads `.env.test` into `process.env` (via `loadEnv` or `dotenv`) and sets `fileParallelism: false`.

## 5. Prisma

- `prisma/schema.prisma` = DDD §3 **verbatim**.
- The first migration `init` is generated by `prisma migrate dev --name init --create-only`. Then **append** DDD §5 items 1 and 2 (partial unique index, CHECK constraint) to its `migration.sql` before applying.
- `.gitignore`: add `src/generated/`.
- `src/prisma/prisma.service.ts`: `PrismaService extends PrismaClient`, constructed with `new PrismaPg({ connectionString: env.DATABASE_URL })`, `$connect` on module init, `$disconnect` on destroy. Global `PrismaModule`.
- Enable Nest shutdown hooks in `main.ts` (`app.enableShutdownHooks()`).

## 6. Common

- `src/common/errors.ts`: `DomainValidationError`, `RetryableError`, `PermanentError`, `RemoteNotFoundError` (all `extends Error`, with `name` set).
- `src/common/zod-validation.pipe.ts`: `new ZodValidationPipe(schema)` → returns the parsed value or throws `BadRequestException({ message: 'Invalid payload', issues })` (issue paths and messages only).
- JSON logging: `NestFactory.create(AppModule, { logger: new ConsoleLogger({ json: true }) })` in production, default otherwise.
- Body size limit: `app.useBodyParser('json', { limit: '2mb' })`.

## 7. Health

`GET /health` (public; guard added in 02 must allow it):
```json
{ "status": "ok" | "degraded", "db": "ok" | "down", "outbox": { "pending": 0, "dead": 0 } }
```
`db` = `SELECT 1` succeeds. `outbox` counts `sync_jobs` by status. HTTP 200 if `db = ok`, else 503.
